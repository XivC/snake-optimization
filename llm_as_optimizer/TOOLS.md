# Инструменты исследовательского агента

Полная справка по 5 инструментам, которые LLM может вызывать через `tool_calls`. Реализация — `llm_research_agent/tools.py`. Дополнительные детали по архитектуре, памяти и протоколу LLM — в [OPTIMIZATION.md](./OPTIMIZATION.md).

**Контекст:** мир детерминирован (один фиксированный сид на весь прогон). `J(θ)` — детерминированная функция от θ. Каждая θ симулируется **ровно один раз**, результат кэшируется. Повторный вызов с той же θ возвращает уже посчитанный `J` и тратит 0 симуляций.

---

## Общие правила

### Поток вызова

```
LLM → response.tool_calls[] → Tool Orchestrator (safe_dispatch)
        ↓ валидация args (ToolValidationError → ok=false, payload.error)
        ↓ диспатч → конкретный tool
        ↓ Evaluator.evaluate_many(...) (одна симуляция на новую θ, кэш для повторов)
        ↓ ToolContext.record_summary(...) → Elite/Anti обновляются
        ← ToolResult{ok, args, payload, simulations_spent}
```

### Лимиты (захардкожены в `tools.py`)

| Параметр | Значение | Где применяется |
|----------|----------|-----------------|
| `MAX_SWEEP_POINTS` | 16 | потолок длины `local_sweep.values` |
| `MAX_PLANE_STEPS` | 9 | потолок `plane_scan.steps` (сетка ≤ 9×9) |
| `MAX_STABILITY_SAMPLES` | 32 | потолок `stability_test.samples` |
| `MAX_NOVELTY_CANDIDATES` | 12 | потолок `novelty_search.n_candidates` |

Превышение клиппится без ошибки. Слишком маленькие значения тоже подтягиваем к минимуму.

### Кэш и `simulations_spent`

`Evaluator` хранит результат симуляции по `theta_key` (округление до 6 знаков). Если для θ уже есть запись, повторный вызов возвращает её мгновенно. `simulations_spent` в `ToolResult` отражает реальный расход — сколько новых симуляций реально запустилось (без кэш-хитов).

Пример: `evaluate_theta(θ)` сразу после bootstrap, где θ уже была оценена → `simulations_spent = 0`.

### Стандартный shape ответа

```jsonc
{
  "tool": "<name>",
  "args": { ... },                 // нормализованная копия (после coerce/clip)
  "ok": true,
  "simulations_spent": 0,
  "result": { ... }                // payload (см. ниже для каждого tool)
}
```

При ошибке валидации:

```jsonc
{
  "tool": "...",
  "args": { ... },
  "ok": false,
  "simulations_spent": 0,
  "result": { "error": "...", "type": "ToolValidationError" }
}
```

Ошибки **видны LLM в `last_tool_results`** на следующем turn — модель учится исправляться.

## 1. `evaluate_theta`

Точечная симуляция одной четвёрки.

### Args

| Поле | Тип | Диапазон | Дефолт | Смысл |
|------|-----|----------|--------|-------|
| `theta` | `[float×4]` | — | (обяз.) | Вектор весов |

### Result

```jsonc
{
  "summary": {
    "theta": [0.9, 0.0, 0.7, 0.0],
    "J": 26.0,
    "apples": 26,
    "steps": 213,
    "died": true
  },
  "improved_elite": false           // true если эта θ стала #1 в EliteArchive
}
```

### Когда использовать

- Точечная проверка конкретного кандидата (например, sparse-варианта `[0, 0, 0, 0]`, `[a, 0, 0, 0]`).
- Подтверждение гипотезы о конкретной точке.

### Стоимость

`1` симуляция, если θ новая. `0`, если θ уже в кэше — но **новой информации не даст**.

## 2. `local_sweep`

1-D scan одной координаты с фиксацией остальных в `center_theta`.

### Args

| Поле | Тип | Диапазон | Дефолт | Смысл |
|------|-----|----------|--------|-------|
| `center_theta` | `[float×4]` | — | (обяз.) | Центральная точка |
| `dimension` | `int` | 0..3 | (обяз.) | Какую координату двигаем |
| `values` | `[float]` | до 16 | — | Явный список значений координаты |
| `radius` | `float` | 0.05..4.0 | 0.5 | Если `values` не задан — симметричная сетка |
| `steps` | `int` | 3..16 | 7 | Если `values` не задан — число точек |

Если задан `values`, поля `radius` и `steps` игнорируются. **Это единственный способ** дотянуться до `0` из угла: `local_sweep(center=[4,0,4,0], dim=2, values=[-2, -1, 0, 1, 2])`.

### Result

```jsonc
{
  "dimension": 2,
  "center_theta": [4.0, 0.0, 4.0, 0.0],
  "samples": [
    {"value": -2.0, "J": 11.0, "died": true, "apples": 12},
    {"value":  0.0, "J": 17.0, "died": true, "apples": 18},
    {"value":  2.0, "J": 24.0, "died": false, "apples": 24},
    {"value":  4.0, "J": 26.0, "died": true, "apples": 27}
  ],
  "argmax_value": 4.0,
  "argmax_J":     26.0,
  "sensitivity_range": 15.0        // max_J − min_J вдоль оси
}
```

### Когда использовать

- Тестирование монотонности по оси и поиск локального пика.
- Sparsity-проверка: явные `values` с включённым `0.0`.
- Подтверждение направления, замеченного в `coordinate_observations`.

### Стоимость

До `len(values)` симуляций минус кэш-хиты.

---

## 3. `plane_scan`

2-D сетка `steps × steps` в плоскости двух координат.

### Args

| Поле | Тип | Диапазон | Дефолт | Смысл |
|------|-----|----------|--------|-------|
| `center_theta` | `[float×4]` | — | (обяз.) | Центр сетки |
| `dims` | `[int×2]` | 0..3, разные | (обяз.) | Пара координат: x и y |
| `radius` | `float` | 0.05..4.0 | 0.7 | Полуразмер сетки по каждой оси |
| `steps` | `int` | 3..9 | 5 | Узлов на сторону (всего `steps²`) |

### Result

```jsonc
{
  "dims": [0, 2],
  "center_theta": [1.0, 0.0, 0.5, 0.0],
  "axis_values": {
    "x_dim": 0, "x": [0.5, 0.75, 1.0, 1.25, 1.5],
    "y_dim": 2, "y": [0.0, 0.25, 0.5, 0.75, 1.0]
  },
  "grid_J": [
    [12.0, 18.0, 22.0, 25.0, 27.0],
    [15.0, 23.0, 28.0, 30.0, 30.0],
    ...
  ],
  "max":   {"value": 33.0, "theta": [0.9, 0.0, 0.7, 0.0], "cell": [3, 2]},
  "local_maxima": [
    {"cell": [3, 2], "value": 33.0},
    {"cell": [0, 4], "value": 27.0}
  ],
  "ridge": [
    {"i_y": 0, "j_x": 4},
    {"i_y": 1, "j_x": 4},
    {"i_y": 2, "j_x": 3}
  ],
  "global_stats": {"min": 12.0, "max": 33.0, "mean": 24.5, "std": 5.1}
}
```

`local_maxima` — узлы, у которых соседи по 4-связности не больше них (топ-5).

`ridge` — argmax по строкам сетки, отфильтрованный по разбросу строки (`max−min ≥ 0.2`). Грубая, но дешёвая «ось» гребня.

### Когда использовать

- Картирование 2-D ландшафта вокруг элиты.
- Поиск гребня при подозрении на коррелированные оси (например, θ0 и θ2).
- Перед длинной серией `evaluate_theta`: быстрый scan показывает форму ландшафта.

### Стоимость

До `steps²` симуляций минус кэш. При `steps=5` — 25 симуляций. Это **самый дорогой** инструмент в типичном бюджете.

## 4. `stability_test`

Локальная устойчивость θ в детерминированном мире: `S(θ) = E_{δ ∼ U(−ε, ε)} |J(θ + δ) − J(θ)|`.

Реализация: возмущения сэмплируются Гауссом с `σ = ε/√3` (типичный L∞-разброс ≈ ε), каждое возмущение оценивается одной симуляцией, результат сравнивается с базовым `J(θ)`.

### Args

| Поле | Тип | Диапазон | Дефолт | Смысл |
|------|-----|----------|--------|-------|
| `theta` | `[float×4]` | — | (обяз.) | Точка, чью устойчивость проверяем |
| `epsilon` | `float` | 0.05..2.0 | 0.25 | Радиус окрестности (L∞ ~ ε) |
| `samples` | `int` | 4..32 | 10 | Число случайных возмущений |

### Result

```jsonc
{
  "theta": [0.9, 0.0, 0.7, 0.0],
  "epsilon": 0.1,
  "base_J": 26.0,
  "samples": [
    {"theta": [0.92, 0.04, 0.65, -0.03], "J": 24.0, "delta_J": -2.0},
    {"theta": [0.85, -0.02, 0.71, 0.05], "J": 22.0, "delta_J": -4.0},
    ...
  ],
  "mean_abs_delta_J": 2.4,
  "stability_score": 0.91,
  "collapse_probability": 0.10
}
```

- `stability_score = 1 − mean|ΔJ| / max(1, |J|)` ∈ [0, 1]: чем ближе к 1, тем стабильнее.
- `collapse_probability` — доля возмущений с падением `J` больше чем на `0.6 · J(θ)`. Сигнализирует «крутой пик», который рискованно ставить в финальное решение.

### Когда использовать

- Перед отчётом о «лучшем» θ: подтвердить, что это не одиночный «иголочный» пик в фиксированном мире.
- При сравнении двух близких по `J` элит — победит более стабильная.
- При выборе центра для следующего `local_sweep`/`plane_scan`.

### Стоимость

`1 + samples` симуляций (база + возмущения) минус кэш. По умолчанию `1 + 10 = 11` симуляций.

## 5. `novelty_search`

Глобальное исследование: max-min greedy в LHS-пуле + список неисследованных знаковых паттернов.

### Args

| Поле | Тип | Диапазон | Дефолт | Смысл |
|------|-----|----------|--------|-------|
| `n_candidates` | `int` | 2..12 | 5 | Сколько новых θ предложить |
| `evaluate` | `bool` | — | true | Если true — сразу симулировать кандидатов |

Алгоритм: генерим LHS-пул из 256 точек в `DEFAULT_BOUNDS = [−4.9, 4.9]^4`. Из пула жадно выбираем `n_candidates` точек, максимизирующих min-distance до уже известных θ (ранее оценённых **или** ранее выбранных в текущем novelty-вызове).

### Result

```jsonc
{
  "n_candidates": 5,
  "evaluated": true,
  "candidates": [
    {"theta": [-3.2, 4.1, -1.8, 0.2], "J": 0.0, "died": true},
    {"theta": [4.6, -2.1, 3.3, -4.8], "J": 1.0, "died": true},
    ...
  ],
  "unexplored_sign_patterns": [
    [-1, -1, -1, 0],
    [-1, 0, 1, -1],
    ...
  ],
  "known_unique_theta": 78
}
```

`unexplored_sign_patterns` — паттерны из {−1, 0, +1}⁴ (нуль — `|θ| ≤ 0.5`), которых ещё нет в кэше. Топ-12 по сортировке. Это **прямая подсказка** агенту: «попробуй sparse-конфигурацию вида (+, 0, +, 0)».

### Когда использовать

- Поддержание `explore_share` в коридоре `[0.20, 0.40]` (`novelty_search` — единственный инструмент, помеченный как `GLOBAL_EXPLORATION`).
- Когда elite перестал расти и есть подозрение на застой в локальной долине.
- На ранних turn-ах для разведки до коммита в exploit.

### Стоимость

`n_candidates` симуляций (если `evaluate=true`) минус кэш. По умолчанию `5` симуляций.

## Обработка ошибок (примеры)

| Ситуация | LLM получит |
|----------|-------------|
| `evaluate_theta` без `theta` | `{"ok": false, "result": {"error": "theta должен быть массивом из 4 чисел; получено None", "type": "ToolValidationError"}}` |
| `local_sweep` с `dimension` строкой | `{"ok": false, "result": {"error": "dimension: ожидалось целое число, получено '...'", ...}}` |
| `plane_scan` с `dims=[0, 0]` | `{"ok": false, "result": {"error": "dims должен быть парой РАЗНЫХ индексов в [0..3]"}}` |
| Неизвестный tool | `{"ok": false, "result": {"error": "Неизвестный tool: 'foo'. Доступные: ['evaluate_theta', ...]"}}` |
| Внутреннее исключение | `{"ok": false, "result": {"error": "RuntimeError: ..."}}` (без traceback в payload) |

Все ошибки сохраняются в `last_tool_results`, поэтому LLM видит свои промахи и поправляет следующий вызов.

## Краткая шпаргалка для LLM

| Хочу | Использую |
|------|-----------|
| Проверить конкретное θ | `evaluate_theta(theta)` |
| Понять направление по одной оси | `local_sweep(center, dim, radius=0.5..1.0)` |
| Дотянуться до 0 из угла | `local_sweep(center, dim, values=[..., 0.0, ...])` |
| Картировать 2-D ландшафт | `plane_scan(center, dims=[i,j], radius, steps=5..7)` |
| Проверить, что элита — не «иголка» | `stability_test(theta, epsilon=0.1, samples=10)` |
| Поддержать exploration ≥ 20% | `novelty_search(n_candidates=5)` |
| Прощупать sparse-паттерн | `evaluate_theta([a, 0, b, 0])` |
