# LLM Research Agent: оптимизация весов политики змейки через tool-calling

Этот документ объясняет «человеческим языком», что именно делает агент в пакете `llm_research_agent`: какую роль играет LLM, какими инструментами она пользуется, что мы ей кладём в промпт, и как мы интерпретируем её ответ. Подробная справка по инструментам вынесена в [TOOLS.md](./TOOLS.md).

**Режим работы — детерминированный.** Один фиксированный сид мира на весь прогон → `J(θ)` есть детерминированная функция от θ. Каждая θ симулируется ровно один раз, результат кэшируется. Никакого Monte-Carlo по rollouts, никакой дисперсии, повторный вызов той же θ бесплатен.

---

## 1. Задача

Политика для змейки — **линейная по 4 признакам**. Для каждого допустимого хода считаем:

```
score(move) = θ0·f_food + θ1·f_danger + θ2·f_space + θ3·f_wall
```

и выбираем ход с максимальным `score`. Признаки `f_*` пересчитываются каждым тиком из состояния поля (см. `player/features.py`).

Качество четвёрки `θ = (θ0, θ1, θ2, θ3)` оцениваем скором одной партии:

```
J(θ) = (число съеденных яблок) − 1·I(змейка погибла)
```

Поскольку сид мира фиксирован, для одной и той же θ начальное положение змейки, последовательность спавна яблок и весь ход партии **полностью воспроизводимы**. `J(θ)` — детерминированная функция, без шума.

Симуляция дорогая, градиент недоступен, размерность маленькая (4), но ландшафт нелинейный — в частности, оптимум часто лежит в *разреженной* (sparse) конфигурации, где половина координат близка к 0.

> **Trade-off фиксированного сида:** мы оптимизируем «политику, которая хорошо играет на конкретном расположении яблок», а не «политику, хорошую в среднем». Зато получаем чистый сигнал без шума, и optimization landscape становится по-настоящему детерминированным.

---

## 2. Главная идея: LLM как исследователь, а не как генератор θ

В предыдущей версии модель просила «выдай 10 четвёрок». Это плохо работало: модель сваливалась в «нарративную» оптимизацию и пропускала очевидно лучшие точки. В этой версии **LLM не возвращает θ напрямую**. Её роль — **управлять экспериментами**:

> «Сними сечение по координате θ2 от −1 до 2 вокруг текущей лучшей точки», или
> «Прогони стабильность вокруг кандидата (0.9, 0, 0.7, 0)», или
> «Поищи новые точки подальше от уже исследованных».

Все θ при этом порождает **сэмплер** (`sampler.py`), а оценивает их **Evaluator** (`evaluator.py`) — через параллельные процессы и с кэшем по уже посчитанным θ.

Распределение ролей:

| Кто | Что делает |
|-----|------------|
| **LLM** | Решает, *какой эксперимент поставить следующим*. Формулирует гипотезы, обновляет `belief_store`. Видит сводку памяти и результаты прошлых экспериментов. |
| **Tool Orchestrator** (`tools.py`) | Принимает tool-call от LLM, валидирует аргументы, дёргает сэмплер и evaluator, возвращает структурированные наблюдения. |
| **Sampler** (`sampler.py`) | Генерирует θ под нужды конкретного инструмента (LHS, perturbation, axis_grid, plane_grid, sparse-зонды, novelty max-min). |
| **Evaluator** (`evaluator.py`) | Запускает партии в `ProcessPoolExecutor`. Один сид мира, одна симуляция на уникальную θ, результат кэшируется. |
| **Memory** (`memory.py`) | Между ходами помнит лучших, провалившихся, гипотезы и сводную «чувствительность» по координатам. |

LLM никогда не дёргает Evaluator напрямую и не видит сырые траектории партий — только то, что приготовил рантайм.

## 3. Что происходит за один turn

Один «turn» = один вызов LLM. Цикл такой:

1. **Собираем payload** (см. §5) — JSON, в котором лежит вся актуальная картина мира: бюджет, лучшие/худшие θ, накопленные гипотезы, чувствительность по осям, последние результаты инструментов, текущие радиусы trust region.
2. **Спрашиваем LLM** через OpenAI-совместимый клиент (`llm_client.py`) с включённым structured-outputs JSON-схемой `research_agent_step`.
3. **Получаем JSON-ответ** с полями `reasoning_brief`, `hypothesis`, `confidence`, `belief_updates`, `tool_calls` (1–4 штуки).
4. **Применяем `belief_updates`** к `BeliefStore` (`add` / `reinforce` / `weaken` / `remove`).
5. **Для каждого `tool_call`** запускаем `safe_dispatch`:
   - валидируем `args` (типы, диапазоны); при ошибке возвращаем LLM `{ok: false, error: ...}` — на следующем ходу она это увидит и поправится;
   - выполняем инструмент → внутри он генерит θ через сэмплер и оценивает их через Evaluator (одна симуляция на новую θ, повторы из кэша бесплатны);
   - результат каждого инструмента сразу обновляет `EliteArchive` и (по эвристике) `AntiArchive`.
6. **Адаптируем trust region** (см. §7): если `best` вырос — сжимаем радиусы, если стоит на месте — расширяем.
7. **Считаем долю exploration**: какая часть выполненных tool-calls была «глобальной разведкой» (`novelty_search`).
8. Стоп-условия: исчерпан `--turns` или `--sim-budget`.

Перед самым первым turn выполняется **bootstrap** (см. §6) — он не вовлекает LLM, но даёт ей с самого начала непустые `elite`, `anti`, `coordinate_observations`.

## 4. Инструменты: как LLM «двигает» эксперимент

LLM может использовать ровно 5 инструментов. Это её «руки»:

| Инструмент | Когда модель его выбирает |
|------------|---------------------------|
| **`evaluate_theta`** | Точечно проверить одну θ. Если θ уже в кэше — это «бесплатное» подтверждение. |
| **`local_sweep`** | Понять, как `J` меняется вдоль одной координаты возле центра. Особенно — задать явный список значений с `0.0`, чтобы из «угла» дотянуться до нуля. |
| **`plane_scan`** | Построить 2-D картинку ландшафта в плоскости двух координат (видно гребни, локальные максимумы, форму). |
| **`stability_test`** | Проверить, что найденный пик не «иголка»: J(θ+δ) для случайных малых δ не должен сильно проседать. |
| **`novelty_search`** | Глобальная разведка — найти точки в пространстве, далёкие от уже исследованных, и (опционально) сразу их оценить. |

Для каждого инструмента в `tools.py` захардкожены лимиты (`MAX_PLANE_STEPS=9`, `MAX_SWEEP_POINTS=16`, …) — превышение клиппится без падения. Стоимость инструмента в симуляциях зависит только от того, сколько новых θ он попросит оценить (повторы кэшируются).

Полные сигнатуры, формат ответа каждого инструмента и стоимость в симуляциях — в [TOOLS.md](./TOOLS.md).

## 5. Что мы кладём LLM в промпт

Сообщение к LLM состоит из двух частей: **system prompt** (роль и правила, не меняется между turn-ами) и **user payload** (свежий снимок состояния, новый каждый turn).

### 5.1. System prompt — постоянные правила

Текст лежит в `prompts.py::SYSTEM_PROMPT`. Кратко он сообщает LLM четыре вещи:

1. **Кто ты**: research-агент, который оптимизирует 4 веса политики змейки. Прямые θ не выдаёшь — пользуешься tool-calls.
2. **Мир детерминирован**: один фиксированный сид, `J(θ)` без шума, повторный запрос той же θ бесплатен и не даёт новой информации — нужно подбирать **новые** точки.
3. **Что у тебя есть**: список 5 инструментов с короткими сигнатурами (как именно их вызывать — JSON-схема обеспечит).
4. **Что копится между ходами**: elite_archive, anti_archive, belief_store, sensitivity-сводка.
5. **Стратегические правила**:
   - 20–40 % ходов — на global exploration (`novelty_search`, далёкий `plane_scan`).
   - Формулируй *falsifiable* гипотезы и обновляй `belief_store`.
   - **Sparsity heuristic**: если элита в углу куба, обязательно проверяй конфигурации, где часть координат принудительно занулена — `local_sweep` с `values=[..., 0.0, ...]` или явный `evaluate_theta([a, 0, b, 0])`. Изотропный sweep малого радиуса вокруг угла никогда не дойдёт до нуля.

### 5.2. User payload — свежий снимок состояния

Это JSON, который собирает `prompts.py::build_user_payload`. По полям и зачем каждое нужно:

```jsonc
{
  // Контекст задачи и бюджета
  "task": "maximize apples on a 10x10 board over N steps with a death penalty; world is deterministic (fixed seed)",
  "turn": 7, "total_turns": 30,
  "budget": {
    "simulations_spent": 89,
    "sim_budget": 2000,
    "note": "1 simulation = 1 unique θ evaluated; repeats are free (cached)."
  },

  // Лучшее, что нашли на данный момент — главный «якорь» для LLM
  "current_best": {"theta": [...], "J": 26.0, "apples": 26, "steps": 213, "died": true},

  // Top-5 элитных θ — чтобы модель выбирала, вокруг кого крутиться
  "elite_archive": [
    {"theta": [4.0, 0.0, 4.0, 0.0], "J": 26.0, "apples": 26, "steps": 213, "died": true},
    ...
  ],

  // Worst-5 с типом провала — чтобы модель не наступала на одни и те же грабли
  "anti_archive": [
    {"theta": [-3.5, 4.0, -2.1, 4.7], "J": -1.0,
     "failure_type": "catastrophic_death", "notes": "died after 3 steps, apples=0"},
    ...
  ],

  // Накопленные гипотезы, отсортированные по confidence
  "beliefs": [
    {"statement": "θ1 ≈ 0 in high-J solutions", "confidence": 0.78, "support": 4},
    ...
  ],

  // Чувствительность по осям внутри элиты (top-5)
  "sensitivity": {
    "per_coord_std":   [0.2, 0.05, 0.3, 0.04],
    "per_coord_range": [[0.6, 1.1], [0.0, 0.05], [0.4, 0.9], [-0.02, 0.02]]
  },

  // Текстовые подсказки про корреляции по всем оценённым θ
  "coordinate_observations": [
    "Positive θ0 strongly correlates with high reward",
    "high-J solutions cluster near 0 on θ3"
  ],

  // Текущий anisotropic радиус trust region — ориентир для local_sweep / plane_scan
  "trust_region_radii_by_coord": [0.5, 0.10, 0.5, 0.05],

  // Сколько % сделанных tool-calls было глобальной разведкой и куда мы хотим попасть
  "exploration_share_so_far": 0.38,
  "exploration_target": [0.20, 0.40],

  // Список разрешённых инструментов и краткая инструкция
  "tool_catalog": ["evaluate_theta", "local_sweep", "novelty_search", "plane_scan", "stability_test"],
  "instruction": "Decide the next 1–3 tool_calls. Update belief_store. Keep global exploration share within [0.20, 0.40]. Do NOT re-evaluate θ that already sit in elite/anti — pick NEW points each turn.",

  // Что вернули инструменты в прошлом turn (последние 4) — главный источник «обратной связи»
  "last_tool_results": [
    {"tool": "local_sweep", "args": {...}, "ok": true,
     "simulations_spent": 7, "result": {"argmax_value": 1.0, "argmax_J": 27.0, ...}},
    ...
  ],

  // Гипотеза, которую модель сама высказывала в прошлый turn — для самоконтроля
  "last_hypothesis": "Optimum likely on the ridge θ0 ≈ θ2 with θ1, θ3 near zero."
}
```

Что сюда **сознательно не входит**:

- сырые траектории партий (модель в них утонет);
- предложения «θ для следующего шага» от рантайма (это исключительно решение модели).

### 5.3. Формат ответа LLM

Структурированный JSON по схеме `research_agent_step` (определена в `llm_client.py`):

```jsonc
{
  "reasoning_brief": "≤800 символов: короткое объяснение, почему такие tool_calls",
  "hypothesis":      "одно предложение, желательно falsifiable",
  "confidence":      0.0..1.0,
  "belief_updates": [
    {"statement": "θ1 ≈ 0 in high-J solutions", "confidence": 0.8, "action": "reinforce"}
  ],
  "tool_calls": [
    {"tool": "local_sweep",
     "args": {"center_theta": [1.0, 0.0, 0.5, 0.0], "dimension": 2, "radius": 0.3, "steps": 7}}
  ]
}
```

JSON-схема включена с `strict=false` — это нужно, чтобы `args` мог быть произвольным объектом (под каждый инструмент свой), а валидацию мы делаем на стороне рантайма с дружелюбными сообщениями об ошибках.

## 6. Память: что копится между turn-ами

Память — главное преимущество перед «zero-shot» промптом. Между turn-ами хранится:

- **`EliteArchive`**: топ-12 θ по `J`, дедуп по округлённому ключу.
- **`AntiArchive`**: до 12 «худших» с пометкой типа провала. В детерминированном режиме классификация упростилась:

  | Условие | failure_type |
  |---------|--------------|
  | `died ∧ J ≤ 0.5` | `catastrophic_death` |
  | `died ∧ apples = 0` | `starvation` |
  | `died ∧ apples ≤ 2` | `early_death` |

  В `notes` лежат конкретные числа (`apples`, `steps`) — модель их видит и понимает, почему точка плохая.

- **`BeliefStore`**: накопленные гипотезы. LLM в каждом turn-е присылает `belief_updates`, рантайм:
  - `add` — новая запись (или объединяется с существующей по нормализованному `statement`);
  - `reinforce` — `confidence += 0.10`, `support += 1`;
  - `weaken` — `confidence -= 0.15`; если стало `< 0.10` — удаляется;
  - `remove` — удалить.

- **`coordinate_observations` и `sensitivity_summary`** — это не отдельные хранилища, а **подсказки**, которые рантайм пересчитывает прямо при сборке payload:
  - `sensitivity_summary` — std и диапазон по каждой координате *внутри элиты*;
  - `coordinate_observations` — словесные наблюдения по *всем* оценённым θ: разница средних в верхней и нижней четверти по каждой оси, и отдельный сигнал `high-J solutions cluster near 0 on θ_k`. Именно это поле толкает модель к sparsity-эксперименту.

## 7. Trust region и адаптация радиусов

Модель не возвращает θ напрямую, поэтому жёсткого клиппинга нет — но мы кладём ей в payload **рекомендуемые радиусы по каждой координате**, чтобы её tool-calls (особенно `local_sweep` и `plane_scan`) были на разумном масштабе.

```python
DEFAULT_RADII = (0.5, 0.10, 0.5, 0.05)   # шире по «сильным» θ0/θ2, уже по θ1/θ3
MIN_RADII     = (0.05, 0.02, 0.05, 0.02)
MAX_RADII     = (1.5, 0.80, 1.5, 0.80)
```

Правило адаптации (выполняется после каждого turn в `agent.py`):

- если `best` вырос на ≥ 0.5 → `radii ← max(MIN, radii · 0.7)` (сжимаем — мы попали в «хорошее место», уточняем);
- если `best` не сдвинулся → `radii ← min(MAX, radii · 1.4)` (расширяем — нужно искать шире);
- иначе оставляем как есть.

## 8. Bootstrap: что мы знаем ещё до первого вызова LLM

Перед `turn 1` рантайм оценивает 54 стартовых θ (без LLM), чтобы у неё уже был непустой elite/anti/обсервации:

- **12 LHS** в кубе `[−4.9, 4.9]^4` — равномерное покрытие;
- **16 corners** — стратифицированные «вершины» куба, ужатые на 15 %;
- **26 sparse axis-probes** — точки с 1 или 2 ненулевыми координатами амплитуды 4.0, остальные = 0.

Третий блок критичен: оптимум змейки часто sparse (вида `(a, 0, b, 0)`), а LHS и corners почти никогда не попадают точно в нули по отдельным осям. Без этих зондов агент в прошлой версии стартовал с очень низким J и не выкарабкивался.

В детерминированном режиме каждая стартовая θ оценивается **ровно один раз**, итого 54 симуляции — секунды на 10 потоках.

## 9. Sampler

`sampler.py` собирает все способы порождения θ. LLM не вызывает его напрямую — он работает изнутри инструментов и bootstrap-а:

- `lhs_box(n, bounds)` — Latin Hypercube;
- `random_uniform_box(n)` — равномерные точки;
- `gaussian_perturb(center, sigmas, n)`, `uniform_box_perturb(center, radii, n, max_changed_coords=2)` — локальные возмущения;
- `axis_grid(center, dim, values)` — сетка для `local_sweep`;
- `plane_grid(center, dims, radius, steps)` — сетка для `plane_scan`;
- `sign_flip_neighbours(center, coords)` — отражения знака;
- `stratified_box_corners(rng, fraction=0.85)` — 16 «вершин»;
- `sparse_axis_probes(amplitudes=(4.0,))` — 26 sparse-зондов;
- `novelty_candidates(known, n_candidates, n_pool=256)` — max-min greedy в LHS-пуле для `novelty_search`.

## 10. Признаки `f_*`

| Признак | Смысл |
|---------|-------|
| `f_food`   | минус городское расстояние от **новой** головы до яблока, нормировано на `H+W` |
| `f_danger` | минус сумма штрафов за стену (`+1`) и тело (`+0.35`) в 4 соседях после хода (хвост, который освободится, не штрафуется) |
| `f_space`  | размер flood-fill области свободных клеток с новой головы, нормировано на `H·W` |
| `f_wall`   | минимальное расстояние от новой головы до края поля |

Если ход недопустим (выход за поле или врезание в тело), это направление в `argmax` не участвует.

## 11. Запуск

```bash
uv run python run_llm_optimization.py \
  --seed 1 --turns 30 --sim-budget 2000 --workers 10
```

Лог пишется в `llm_research_agent/logs/agent_seed_<seed>_<timestamp>.log`.

| Флаг | Смысл |
|------|-------|
| `--seed N` | RNG seed мира (обязательный) — фиксирует один-единственный мир, по которому оптимизируем |
| `--turns K` | сколько обращений к LLM |
| `--steps S` | лимит шагов на партию (по умолчанию 1000) |
| `--workers W` | параллельные процессы (`0` = число ядер) |
| `--bootstrap-n N` | размер LHS-набора (corners и sparse добавляются автоматически) |
| `--sim-budget N` | опциональный максимум симуляций (= уникальных θ); по достижении — стоп |
| `--llm-timeout SEC` | HTTP таймаут к API |
| `--log-dir DIR` | каталог логов |

## 12. Состав пакета

| Модуль | Что внутри |
|--------|------------|
| `agent.py` | главный turn-loop, bootstrap, CLI, логи |
| `evaluator.py` | `Evaluator` — детерминированная симуляция, кэш по θ, параллелизм |
| `sampler.py` | LHS, gaussian/uniform perturbation, axis/plane grid, sparse probes, novelty max-min |
| `tools.py` | 5 инструментов + диспетчер с валидацией; `ToolContext` |
| `memory.py` | `EliteArchive`, `AntiArchive`, `BeliefStore`, `coordinate_observations`, `sensitivity_summary` |
| `trust_region.py` | anisotropic per-coord radii + `adapt_radii(improved, stalled)` |
